# Project design review

Reviewed 14 October 2026. Repository-wide static review of application code, tests, configuration, deployment scripts, and tracked/ignored layout. Dependency internals, lockfile contents, fonts, APK/JAR binaries, secrets, and live production state are outside scope. Findings describe the current code; passing tests do not rule them out. This is an actionable inventory, not a guarantee that no further defects exist.

**Priority:** P1 = correctness/data-loss risk; P2 = maintainability/reliability problem; P3 = cleanup. Locations are repository-relative; named symbols locate the implementation without relying on unstable line numbers. Each numbered entry is a separate patch target.

## 1. Filesystem, names, Git, and repository boundaries

| ID | Priority / location | Specific problem → patch direction |
|---|---|---|
| F01 | P2 · root `letta/`, `infrastructure/letta/`, `backend/src/assistant/letta.ts`, `backend/src/routes/letta.ts` | “Letta” names four different responsibilities: runtime extensions, image patching, SDK access, and callbacks. Group extensions and image compatibility under a documented integration boundary; rename client and callback modules by role. |
| F02 | P2 · `backend/src/assistant/` | The folder mixes domain rules, storage, SDK/socket adapters, workspace I/O, prompt loading, event transport, and orchestration. Separate conversations/calls/background domains from Letta and filesystem adapters; avoid another generic dumping-ground folder. |
| F03 | P2 · `backend/src/devices.ts`, `device-mcp.ts`, `device-files.ts` | Device registry and HTTP routes share one root module, while related transport/storage helpers are scattered beside unrelated auth/link modules. Create a `devices/` feature with hub, API, MCP adapter, and file-transfer modules. |
| F04 | P2 · `frontend/src/components/assistant-ui/elements/` | A single “elements” directory mixes complete thread/composer screens, provider-specific tool parsers, media widgets, file viewers, markdown infrastructure, and generic style helpers. Organize by chat/composer/tools/files/markdown; retain a small clearly marked vendor layer only if needed. |
| F05 | P3 · frontend filenames | `.aui.tsx` and plain `.tsx` encode no reliable boundary: `reasoning.aui.tsx`/`reasoning.tsx`, `tool-fallback.aui.tsx`, and `markdown-text.tsx` are all customized application code. Use one naming convention; rename the reasoning pair to distinguish message adapter from disclosure UI. |
| F06 | P2 · `backend/src/chat-types.ts`, frontend `@backend/*`, frontend Dockerfile | The public contract physically belongs to backend implementation; frontend builds require a manually copied sibling backend file. Move API schemas/types into a small shared contract package and restrict imports to that package. |
| F07 | P2 · root package/build configuration | There is no root workspace or aggregate check command. Two JS lockfiles/package configurations plus Python/device/mod tests must be discovered separately. Provide root orchestration that pins the tools and runs all relevant checks without merging unrelated language environments. |
| F08 | P2 · `mobile/Artemis.apk`, `mobile/install.ps1` | A compiled APK is tracked, and the installer always prefers it over a newly built APK. Fresh source changes can install an old binary. Publish APKs as release artifacts; make installation select the current build or an explicit artifact path. Keep the Gradle wrapper JAR tracked. |
| F09 | P2 · `.dockerignore` | Both app images send the repository root as build context. Mobile `.gradle`, `build`, `local.properties`, `.signing`, APK, and Python test/lint caches are not excluded. Exclude unrelated project trees/generated/private files or use explicit per-image allowlists. |
| F10 | P2 · root and package `.gitignore` files | Ignore policy is scattered and incomplete for likely local files: `.env.production`/`.env.development`, generic logs, and keystores outside `mobile/.signing` are not covered. Consolidate/document patterns, explicitly allow `.env.example`, and keep source/locks/generator output that builds require. |
| F11 | P2 · `backend/src/assistant/present-tool.json`, frontend generator/test | A generated frontend-library schema is committed under backend handwritten source. Its owner and regeneration dependency are obscured. Put generated contracts in an explicitly generated location; run generation/drift validation from the root build. Do not simply Git-ignore the schema while the backend requires it. |
| F12 | P2 · `backend/.workspace`, Compose mounts | Durable user files and backend state live beneath a disposable source checkout; deployments then substitute different absolute paths. Make the data root an explicit validated configuration outside source, with clear ownership for attachments, device exports, screenshots, and state. |
| F13 | P3 · `devices/artemis-device.py`, `devices/test_device.py` | A hyphenated Python module forces path/import workarounds; its test naming/layout also differs from the agent package. Use an importable `artemis_device` package/module with a small CLI entrypoint and dedicated tests directory. |
| F14 | P2 · both production Compose files, HTTPS setup, Coolify scripts, mobile activity | Environment-specific hostnames, storage paths, application/user IDs, and ports are embedded in source. Move deployment identity into configuration; keep example values in docs. Derive the mobile trusted host from the configured build URL. |
| F15 | P3 · README and deployment documentation | The root README mixes architecture, operational instructions, provider workarounds, measured historical latency, and limitations. Split architecture/development/deployment/provider notes and preserve a short root index; remove obsolete Next.js latency framing and stale auth comments. |

**Git verification:** `.env`, backend workspace, frontend output, Python environments/caches, Android build/cache/local settings/signing directory, `.codex-tmp`, and `.pnpm-store` are currently ignored. No tracked file matched the current Git-ignore rules. Lockfiles, referenced fonts, and the Gradle wrapper are legitimate tracked inputs; do not delete them as “unused.”

## 2. Macro design and excessive responsibilities

| ID | Priority / location | Specific problem → patch direction |
|---|---|---|
| M01 | P2 · backend runtime/background/conversations modules | Circular dependencies: runtime ↔ background; runtime → conversations → background → runtime. Domain policy knows how to launch SDK sessions and project HTTP summaries. Inject delivery/event/storage ports and wire dependencies in a composition root. |
| M02 | P2 · backend `calls`, `events`, `background-store`, `runtime`, `letta`, `native-tools`, `devices` | Module-level mutable singletons and import-time timers/hooks hide ownership and prevent isolated lifecycle tests. Instantiate an application context with explicit start/close methods; retain single-instance deployment if that is the product requirement. |
| M03 | P2 · `backend/src/assistant/runtime.ts` (687 lines) | One module handles turn scheduling, sockets, notification claiming, message projection, tools, model selection, titles, reflection, and eviction. Extract a session adapter/reader, turn executor, scheduler, and registry with explicit contracts. |
| M04 | P2 · frontend `thread.aui.tsx` (1,057 lines) | Thread layout, message renderers, composer/recording controls, day headers, focus handling, grouping, animation, and actions coexist. Split by these responsibilities and keep one short thread composition component. |
| M05 | P2 · frontend `tool-fallback.aui.tsx` (1,077 lines) | Tool details, shell/search output, receipts, approvals, questionnaires, and generic compound-component exports are combined. Extract only supported tool renderers; isolate or remove the unsupported approval framework. |
| M06 | P2 · frontend `use-conversation.ts` (385 lines), `use-chat-runtime.ts`, `chat-app.tsx` | Conversation state is spread across many state variables, mirrored refs, fresh/carry flags, optimistic messages, two queues, and selected-versus-shown IDs. Use a per-conversation reducer/store with explicit request and turn states; keep assistant-ui as an adapter. |
| M07 | P2 · frontend image/file/thread-list modules | `image.tsx` (601 lines), `file.tsx` (368), and `thread-list.aui.tsx` (542) retain library-sized compound APIs and optional variants for a small app. Extract media helpers and current UI; remove unconsumed exports/variants after checking call sites. |
| M08 | P2 · `devices/artemis-device.py` (351 lines), Android `MainActivity` | Device CLI/menu, credentials, SSE, RPC subprocess, transfers, execution, and reconnect are coupled; Android setup mixes permission/file/navigation/theme callbacks in `onCreate`. Split transport/lifecycle from UI and platform adapters. |
| M09 | P2 · frontend `globals.css` (577 lines), `generative-ui.css` (996) | Global theme, animation, mobile layouts, vendor selectors, and broad overrides share large stylesheets. Separate tokens/layout/features/vendor styles; scope generative rules to their root and document maintained vendor source/version. |
| M10 | P2 · frontend hooks and settings | Every component handwrites fetching, JSON casting, error extraction, and session failure behavior. Add a small typed API layer with shared status/error handling, cancellation, and response validation; no large framework is required. |
| M11 | P2 · SDK/protocol boundaries across backend | `as never`, broad `Record<string, unknown>`, casts of fetched JSON, and array-as-object parsers erase boundary guarantees. Introduce validated SDK/HTTP adapters; preserve unknown/raw values separately for diagnostics. |
| M12 | P2 · `messages.ts`, task notification parsers, tool display/web-search parsers | Application metadata and provider/tool identity are recovered from XML-like text, shell commands, and human output wording. Centralize/version these codecs, prefer structured events/results, and keep legacy decoding separate from current encoding. |

## 3. Backend correctness and micro design

| ID | Priority / location | Specific problem → patch direction |
|---|---|---|
| B01 | P1 · `assistant/voice-input.ts::newVoiceInput` | Deduplication uses utterance text: saying “yes” again within the last eight phrases is dropped, including across calls; input is marked forwarded before the turn succeeds. Deduplicate by request/utterance identity scoped to a call and acknowledge after acceptance. Expire entries. |
| B02 | P1 · background `deliverAsText`, `takeHeldUpdates`, `takeQueuedUpdate`; voice `takeUpdate` | Results become `delivered` and leave pending sets before generation succeeds. Failures/aborts can leave no transcript and no retryable held result. Introduce claimed/inflight/completed delivery with rollback/recovery and an idempotent acknowledgement. |
| B03 | P1 · `background-store.ts::load/save` | Any read/parse error silently produces empty state, then a subsequent save can overwrite recoverable data. Shapes are cast, not checked. Validate/version the file; distinguish missing from corrupt/unreadable and preserve bad files. |
| B04 | P1 · `background-store.ts::save` | Pruning deletes the oldest updates regardless of held/queued/unread status; unfinished results can disappear after 300 entries. Retain unresolved records; prune acknowledged terminal records under an explicit retention policy. Also expire abandoned origins. |
| B05 | P2 · background store and mutable `state()` | Callers mutate storage directly and synchronously rewrite/sort the entire file on many event transitions. Encapsulate mutations and use serialized asynchronous persistence or a small transactional store. Persist before acknowledging notification ownership. |
| B06 | P1 · `runtime.ts::SessionReader.pump/nextTurn` | `void this.pump()` has no rejection handler; exceptions skip the terminal null signal. An unexpected end/error before a sink is attached is not retained. Waiting turns can hang. Track reader terminal state, signal it in `finally`, and reject waiting turns deterministically. |
| B07 | P1 · runtime registry eviction, `close`, `closeConversationRuntime` | Eviction uses last-used time rather than active/queued state, so a turn over 15 minutes can be closed. Closing/removing a runtime does not drain/cancel queued turns; a new runtime can overlap the old scheduler. Give runtimes an explicit closing state and only evict idle ones. |
| B08 | P1 · `runtime.ts::waitUntilIdle` | Status request errors are interpreted as idle; reaching the deadline also returns as if ready. Throw a distinguishable busy/unreachable error and honor cancellation before sending another stateful turn. |
| B09 | P2 · `ConversationRuntime.run`, `SessionReader.nextTurn`, `http.ts::eventStream` | Promise chains and message/SSE buffers have no admission or backpressure limit. A connected client can enqueue indefinitely. Bound pending turns/buffered data and reject or disconnect slow consumers predictably. |
| B10 | P1 · runtime `claimNotifications`; `letta/notifications.mjs` | Notifications are removed/claimed based on tag presence before confirming successful parsing/acceptance. The mod accepts any successful HTTP response, ignoring `accepted`; malformed blocks can be discarded. Parse/validate first, acknowledge exact notification IDs, and retry failed claims. |
| B11 | P2 · `SessionReader.claimed`, runtime `autoTitle` | Claimed IDs are kept indefinitely and failed removals stay claimed, preventing retry. Auto-titling also overwrites a user's rename if its async request finishes later. Bound/release claim state and guard title writes with a version or empty-title precondition. |
| B12 | P2 · `runtime.ts::openSession` | Failures after creating/readying the local session reject the cached promise without closing that local resource. Wrap initialization in cleanup-on-failure and publish only fully initialized sessions. |
| B13 | P1 · `routes/conversations.ts`, `routes/voice.ts` | Request casts substitute for validation: non-string `text`, non-array attachments/messages, or null bodies can throw or enter unexpected paths. Validate complete bounded payloads before accessing fields; consistently return 400 for invalid input. |
| B14 | P1 · conversation routes and voice agent routes | Ownership/existence/archive checks are inconsistent: rename/archive/history/SSE/cancel and internal voice paths can act on arbitrary IDs. Apply one conversation guard before access or runtime creation; explicitly handle trusted internal exceptions. |
| B15 | P1 · `conversations.ts::deleteFromMessage`, archive routes | History fork/archive operations bypass turn serialization. Running/queued turns may write into the archived source; background state stays keyed to the old ID. Coordinate lifecycle mutations with the scheduler and define migration/cancellation for task origins, results, read state, and active calls. |
| B16 | P2 · conversation list/history/attachment detection; assistant identity lookup | Hard limits of 100 conversations, 300 history rows, and 1,000 identity lookup rows silently truncate. Attachment detection can miss older attachments; oldest-conversation inference can pick the wrong default. Implement cursors and explicit identity, or expose limits as product behavior. |
| B17 | P2 · `getConversation`, HTTP `errorResponse` | Catch-all lookup errors become “not found,” while other routes return raw internal exception strings to browsers. Map typed not-found/unavailable/validation errors; log details internally with request IDs. |
| B18 | P2 · file upload/transcription routes; `useVoiceRecorder` | Multipart bodies are materialized before application size checks; transcription/recording has no bounded size/duration. Add request limits before parsing, bounded recordings, upload cancellation, and provider deadlines. |
| B19 | P2 · workspace attachments/screenshots/device exports | Uploads and screenshots have no ownership/retention cleanup; adapter removal is a no-op and discarded sends leave files behind. Record references and collect abandoned uploads safely; keep user outputs under a separate retention rule. |
| B20 | P2 · `workspace.ts::resolveAttachments`, `files.ts` | Attachment kind/MIME are partly trusted from clients despite inspecting bytes. File serving also omits byte-range support used by media/PDF viewers. Derive authoritative metadata on the server and implement bounded range/HEAD handling. |
| B21 | P2 · `messages.ts::stripCallState/decodeUserContent` | State markers are removed anywhere, including legitimate text examples, and user strings resembling metadata can be decoded as app events or hidden. Parse an explicit trailing control marker and a versioned envelope that separates user text from app metadata. |
| B22 | P2 · `mcp/settings.ts::readMcpServers` | Malformed disk entries are intentionally returned as `McpServer`; downstream skill rendering calls `server.name.replace` and can crash. Keep invalid entries visible as diagnostics, but exclude them from operational typed lists until validated. |
| B23 | P2 · MCP registry/service/native-tools; `internal-tools/install.ts::syncMods` | Settings/files are saved before catalog/prompt/mod sync succeeds, yet the API reports failure. A failed mod reload is not retried if the file already matches next time. Separate durable save from synchronization status and track/retry unapplied revisions. |
| B24 | P2 · MCP client/catalog and inline tool registration | One fresh handshake per call, uncapped cursor loops/server fan-out, and mismatched 60-second inline versus 120-second MCP timeouts. Cap pages/tools/concurrency, align end-to-end deadlines, propagate cancellation, and consider transport reuse where useful. |
| B25 | P2 · `mcp-bridge/client.ts::textOfResult` | Images are silently dropped except device screenshots; resources are replaced by “omitted,” and structured content disappears when any text exists. Preserve a structured result envelope and explicitly convert supported media/resources to workspace artifacts. |
| B26 | P2 · config/auth/Letta-server lifecycle | Environment loading/validation occurs on import; numeric/timezone settings are unchecked; default internal/LiveKit secrets remain usable. Server setup has no graceful teardown/readiness endpoint for its own dependencies. Validate config once at startup and explicitly own connection/timer shutdown. |
| B27 | P2 · `assistant/present.ts`, generative UI renderer | The backend only checks component names: null/scalar trees can be “shown,” props/actions are not checked, recursion is unbounded, and frontend rendering has no local error boundary. Validate bounded trees and supported actions/props; render a recoverable fallback on errors. |

## 4. Frontend behavior and code writing

| ID | Priority / location | Specific problem → patch direction |
|---|---|---|
| U01 | P1 · `use-conversation.ts`, backend events | SSE has no event sequence/replay/snapshot; reconnect does not refetch state. Opening a chat mid-turn misses `turn_start`/task-start and can show idle; losing `turn_end` leaves it busy. Add an active-turn/task snapshot and reconcile on every connection. |
| U02 | P1 · conversation history/live merge | Initial history and live backlog overlap without stable reconciliation; independent refetches can finish out of order. On failed end-of-turn history fetch, live items are still deleted. Merge by canonical IDs/revision, discard stale responses, and retain live content until successful reconciliation. |
| U03 | P1 · `useConversation::send`, optimistic echo matching | A three-second timeout is treated as subscription readiness; sends have no client message ID and match echoes using text plus attachment count. Disconnected sends can lose their live reply or match the wrong message. Use connection state and server-acknowledged client IDs. |
| U04 | P1 · `useChatRuntime`, `shownId` versus `activeId` | While switching, old history remains visible but editing/deleting targets the newly selected ID. Async send/error handlers also update whichever chat is now displayed. Bind every action/result to its owning conversation; disable incompatible actions during transition. |
| U05 | P1 · `use-conversations.ts::remove/refresh`, settings persistence | Archive ignores HTTP failure and removes the row anyway. Refresh/poll requests can overwrite newer mutations; entire MCP lists are saved from stale state, with editing keyed by index. Check responses, serialize/version requests, edit by identity, and reject conflicting saves. |
| U06 | P2 · `useConversation::markRead`, `ChatApp::startCall`, sign-out | Read failures never rollback; call startup errors only reach the console; logout reloads without checking success. Give operations explicit pending/error/retry behavior and keep state consistent with server acknowledgement. |
| U07 | P2 · both conversation EventSource handlers | `JSON.parse` and type assertions trust event data without validation or error handling. Reject malformed/unknown events without crashing handlers, record diagnostics, and trigger reconciliation. |
| U08 | P2 · `workspace-file.tsx::infoRequests`, markdown metadata cache | File metadata is cached forever with no bound/invalidation, despite files being rewritable. Link failures are cached as success-like empty objects. Add TTL/size limits, invalidate changed files, and distinguish retryable failures. |
| U09 | P1 · `lib/mcp-servers.ts::toDraft/fromDraft` | Joining args with spaces then splitting whitespace corrupts arguments containing spaces/quotes; malformed env/header lines are silently skipped. Use a JSON array/one-argument-per-row editor and show parse errors instead of discarding input. |
| U10 | P2 · `chat-app.tsx`, `auth-gate.tsx` | Effort localStorage access can throw, unlike theme storage; overlapping focus auth checks can overwrite login state and unmount an active call on a temporary network error. Guard storage and distinguish unauthenticated from unreachable with request generation tracking. |
| U11 | P2 · `chat/mascot.tsx` | A permanent animation loop scans DOM/text nodes and reads geometry every frame, including when hidden/settled. It also mutates message layout attributes outside React. Use refs/observers and run frames only during movement/pointer activity; honor reduced motion in JS. |
| U12 | P2 · audio visualizer animator, composer waveform, global mobile CSS | The visualizer schedules renders even for static sequences; waveform reads layout/computed style every frame. Global selectors infer control semantics from `aria-label`/class names and use forced dimensions. Cache geometry/styles, pause static animation, and style explicit component slots. |
| U13 | P2 · workspace panel, `image.tsx::ImageZoom` | Mobile file preview behaves as a modal overlay without focus trapping/restoration or background inertness. Image zoom handwrites a second modal implementation beside existing Radix dialogs. Reuse one accessible dialog/desktop-panel shell. |
| U14 | P2 · markdown link previews and favicons | Regex scans treat URLs inside code/examples as links and eagerly fetch every preview; several favicon policies contact external services automatically. Parse actual markdown link nodes, cap/lazily load previews, and centralize the icon policy with reliable fallback. |
| U15 | P3 · media/file/tool UI helpers | JSON parsing, file-size/MIME handling, markdown configuration, duration formatting, and fallback serialization are duplicated. Move pure helpers to owned modules; keep provider-specific parsing in adapters rather than display components. |

## 5. Voice agent, devices, Android, and operations

| ID | Priority / location | Specific problem → patch direction |
|---|---|---|
| O01 | P1 · `devices/scopes/media.py::control` | macOS eagerly builds a script dictionary containing `round(volume)` even for play/pause/info, where volume is normally `None`; those actions fail. Construct the volume script only for that action and test all actions per platform. |
| O02 | P2 · device SSE loop and `StdioMcp.rpc` | Main-thread tool execution blocks heartbeat/event processing; long calls/network uploads can consume the lease. Stdio response waiting discards unrelated responses and uses unbounded queues. Separate heartbeat from execution, bound queues, and either serialize RPC explicitly or route responses by ID. |
| O03 | P2 · device `main`, `StdioMcp.__init__/close`, terminal scope | Failed initialization can leak a subprocess; a dead stdio server is repeatedly reused; `Queue.get` timeouts raise uncaught `queue.Empty`; terminal output cuts lack diagnostics. Use context-managed ownership, restart dead transports, convert RPC timeouts explicitly, and report truncation/unknown outcomes. |
| O04 | P2 · device scopes and backend `DeviceHub` | Scope registration accepts a large untyped argparse object and builds handlers via nested closures; hub combines leases, queues, auth, retry, storage coordination, and routes. Use small typed scope settings and extract hub transport/API adapters. Replace repeated lease/deadline literals with protocol constants. |
| O05 | P1 · `CallController::_after_response/aclose/_spawn` | Hangup timers use `asyncio.create_task` outside `_tasks`, can overlap, and survive `aclose`. Other tasks are discarded without retrieving exceptions; update-stream failure can terminate the delivery worker. Supervise all tasks, cancel the previous end timer, detach event handlers, and recover delivery failures. |
| O06 | P2 · `agent/src/voice_agent/gateway.py` | Ordinary state/ack/end calls inherit long default HTTP timeouts; SSE waits forever with no stalled-channel detection. UTF-8 decoding is not flushed at update EOF. Set operation-specific deadlines/heartbeat watchdog and flush the decoder; preserve explicit cancellation. |
| O07 | P2 · Android `MainActivity`, build/install configuration | Permission results are not bound to the current navigation/lifecycle; transient network errors can stack dialogs. Downloads/new-window file previews lose the WebView session in an external browser. Track pending request ownership, deduplicate errors, and implement authenticated download/open behavior intentionally. |
| O08 | P2 · `docker-compose.yml`, `docker-compose.coolify.yml` | Almost the whole stack is duplicated; fixes must be copied across files, and Letta startup/nginx config is embedded shell. Maintain one base plus environment overrides; extract tested entrypoint/config templates and add service health checks. |
| O09 | P1 · `infrastructure/https/setup.sh` | Setup finishes by requesting authenticated `/api/conversations` without a cookie, so a healthy protected deployment returns 401 and setup fails. | O10 | P2 · Coolify `poll-deploy.py`, `rotate-token.py` | Deployment records the observed commit before triggering an unpinned branch deployment and later treats missing actual commit as success. A failed SHA is never retried automatically; token validation failure leaves issued tokens behind. Require actual deployed revision, add explicit retry policy, and rollback/clean up incomplete rotation. |
| O11 | P2 · `letta/telnyx.mjs`, bundle patch and its tests | Provider capabilities/cost/context limits are hardcoded for all discovered models; compatibility depends on exact bundled source and transitive package paths. Isolate/version this compatibility adapter, report unknown capabilities honestly, and automate tests against the pinned upstream bundle. |

## Verification and patch order

- Backend: typecheck and lint passed; **84 tests passed**.
- Frontend: typecheck passed; **53 tests passed**; lint has two warnings (`surfaces.tsx` effect dependency, unused auth `body`).
- Voice agent: **12 tests passed**; Ruff and Pyright passed.
- Device client: **10 tests passed**. Letta mods: **7 tests passed**.
- Direct reproductions confirmed B01 (a second spoken “yes” returns empty), B27 (`presentOutcome(null)` reports success), and O01 (macOS play raises `TypeError` without a volume value).
- The Groq bundle compatibility suite requires `LETTA_BUNDLE` and was not run. Android builds, Docker deployment, and real microphone/WebRTC/platform UI behavior were not exercised.
- Existing coverage is mostly pure codecs/policy/adapters plus device/auth integration. Add regression coverage for B01–B15, U01–U05, O01/O05/O09; there are no React behavior tests or end-to-end chat/call recovery tests in the tracked tree.

Patch in small independent changes: **P1 regressions → delivery/session lifecycle → shared contracts and dependency boundaries → dead code → filesystem moves/naming → UI/style simplification → deployment consolidation**. Keep file moves separate from behavior changes so reviewers can follow the patch. Preserve legacy history decoders until stored histories have an explicit migration path.
